Every interactive feature of the PNetLab web UI rides this same-origin
REST surface, so anything the UI can do, a script or AI agent can do too.
The surface has three layers:
1. The core Slim application at /api/... (labs, nodes, networks, folders,
   templates, import/export, authentication).
2. Per-feature sub-applications at /<app>/api.php?action=... (status,
   users, cluster, images, PKI, MCP administration, ...). These are plain
   PHP dispatchers keyed on an "action" request parameter.
3. Lab-page helper endpoints at /pnq-*.php (live link statistics, per-node
   telemetry history, protocol overlays, packet watchers, ...) scoped to
   the caller's open lab session.
Authentication is a session cookie: POST /api/auth with username/password
sets an HttpOnly, Secure, SameSite=Strict "token" cookie which every other
endpoint validates. The appliance is served over HTTPS only (HTTP 301s to
HTTPS for non-loopback clients) and the cookie is Secure-flagged, so
clients MUST talk https and keep a cookie jar.
Two response envelopes exist, for historical reasons:
- Engine envelope (most endpoints): {"code": int, "status":
  "success"|"fail"|"unauthorized", "message": str, "data": any}
- Compatibility envelope (a few status/api.php actions): {"result": bool,
  "message": str, "data": any}
A machine agent should key on the HTTP status first, then "status" or
"result".
A separate MCP (Model Context Protocol) endpoint at /mcp/ exposes the
build-and-run surface as typed tools for AI agents; see mcp-tools.json
and the MCP administration tag below.

auth

Login, logout and session introspection.

GET /api/auth

Current session and user profile.

Returns the logged-in user's profile (username, role, pod/tenant id,
html5 console preference, workspace folder, language table) in the
engine envelope. 401 when the token cookie is missing or stale - use
this as the cheap "am I still logged in?" probe. Query parameter
"lang" selects the UI language table merged into data.lang.
ParameterInDescription
langqueryOptional UI language code merged into the reply.
curl -sk -b jar.txt https://<host>/api/auth

POST /api/auth

Log in and receive the session cookie.

Body: {"username": str, "password": str, "html5": "0"|"1" (optional
initial console preference)}. On success (200, message id 90013) the
response sets the "token" cookie (HttpOnly, Secure, SameSite=Strict).
Failure modes:
- 401 (90002) invalid credentials - counts one failed attempt for the
  client IP.
- 403 (90003..90006) correct password but the account is contained:
  not yet active, expired, outside its scheduled days, or disabled.
  Does NOT count against the throttle.
- 429 (90007) the IP exceeded 10 failures in 300 s; blocked 300 s,
  Retry-After header carries the remaining seconds.
- 503 (90020) the account is flagged for external authentication
  (RADIUS/LDAP), the directory is unreachable, and local-hash
  fallback is disabled. Not a credential failure - retry later or
  contact the administrator. No throttle strike.
Accounts flagged external (users.ext_auth = radius|ldap) are verified
against the configured directory; every other account authenticates
against its local password hash.
curl -sk -c jar.txt -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"..."}' \
  https://<host>/api/auth

GET /api/auth/logout

Log out and clear the session cookie.

Invalidates the server-side session and expires the token cookie.
curl -sk -b jar.txt https://<host>/api/auth/logout

GET /api/health

Liveness probe (no authentication).

Returns 200 with a tiny JSON body when the web tier and database are
answering. Safe to poll; used by installers and load balancers.
curl -sk https://<host>/api/health

templates

Node templates, template icons and per-template defaults.

GET /api/list/networks

List network/cloud types available to the caller.

Admins see every network type including host-bridged clouds
(pnetN/bridge interfaces); non-admin users get the restricted list.

GET /api/list/template-icons

List selectable node icons.

Returns the icon filenames under /opt/unetlab/html/images/icons that
the node editor offers.

GET /api/list/template-types

List the node type families.

Returns the engine's node type map (iol, qemu, docker, dynamips,
vpcs).

GET /api/list/templates/{template}

List node templates, or the form schema of one template.

Without a template slug: data maps every installed template slug to
its display name; templates whose image is missing are suffixed
".missing". With a slug (e.g. iol, vios, docker): data.options is the
add-node form schema (name, type, image list, cpu, ram, ethernet, and
per-type extras) - the exact field set POST
/api/labs/session/nodes/add accepts.
ParameterInDescription
templatepathTemplate slug; empty for the full template map.
curl -sk -b jar.txt https://<host>/api/list/templates/

GET /api/templatedefaults/{template}

Read saved per-template form defaults.

Returns the admin-saved default values applied when the add-node form
opens for this template.

POST /api/templatedefaults/{template}

Save per-template form defaults.

Body is the field/value map to preset. Admin only.

DELETE /api/templatedefaults/{template}

Reset per-template form defaults.

Removes the stored defaults for the template. Admin only.

labs

Lab files - create, clone, read, edit, move, delete.

POST /api/labs

Create a new lab, or clone an existing one.

Create - body {"path": folder, "name": str, "version": str,
"description": str, "body": str}. Clone - body {"source":
"/Folder/Lab.unl", "name": new-name}; presence of "source" selects
the clone path. Returns the new lab in data.
curl -sk -b jar.txt -H 'Content-Type: application/json' \
  -d '{"path":"/","name":"demo","version":"1"}' \
  https://<host>/api/labs

DELETE /api/labs

Delete a lab file.

Body {"path": "/Folder/Lab.unl"}. Also removes a corrupt lab file
that can no longer be parsed.

POST /api/labs/{action}

Read or modify one lab file.

Body always carries {"path": "/Folder/Lab.unl"} plus per-action
fields. get - lab metadata; preview - one-shot bundle of labinfo +
nodes + networks + text objects + lines (what the preview pane
renders); edit - body.data carries the changed lab attributes
(name, description, body, version, ...); move - body.new_path is the
destination folder.
ParameterInDescription
action reqpathOne of the x-actions values.

Actions: edit get move preview

lab-session

Running-lab sessions - open/join/leave/destroy a session, read topology objects, and drive every canvas mutation through the object/action fan-out.

POST /api/labs/session/factory/{action}

Lab-session lifecycle (open/join/leave/destroy/stop).

create - body {"path": "/Folder/Lab.unl"}; opens (or re-opens) a
session for the lab and points the caller's account at it. join -
body {"lab_session": id} joins a shared session. leave - leaves the
caller's current session. destroy - body {"lab_session": id} tears
the session down (stops its nodes, frees resources); also repairs
half-broken sessions. stopNodes - body {"lab_session": id} stops all
nodes but keeps the session. Resource limits (per-user CPU/RAM caps,
running-node limits) are enforced on create/start.
ParameterInDescription
action reqpathOne of the x-actions values.
curl -sk -b jar.txt -H 'Content-Type: application/json' \
  -d '{"path":"/demo.unl"}' \
  https://<host>/api/labs/session/factory/create

Actions: create destroy join leave stopNodes

PUT /api/labs/session/network/manage

Save a network's managed settings (wireless cell WLANs).

Persists managed network attributes for the open session - primarily
the wireless-cell WLAN list - and live-applies the change by
restarting cabled, cell-driven access points.

POST /api/labs/session/nodestatus

Node status of the caller's open lab session.

The topology page's status poll. Optional body field lab_session pins
a specific joined session (protects a second tab of the same account
from repointing the poll).

GET /api/labs/session/{object}

Read one object family of the caller's open lab session.

The read fan-out of the lab page. object selects what is returned
(see x-objects): info - lab metadata; topology - the full canvas
bundle; nodes - node list with status, console host/port and url;
networks - network list; links - wiring; interfaces /
networkints / interface - per-node and per-network interface detail
(query: id); configs - saved startup-configs; textobjects /
pictures / picturemapped / picturedata - canvas annotations (query:
id where applicable); line - drawn line objects; workbook - workbook
pages; tasks - the kind="task" view of workbook storage (optional
query: name); wireshark - capture definitions; multi_cfg_list /
multi_cfg_detail - config sets; portcheck - console-port
reachability; console_guac_link - HTML5 console link mint; html -
rendered lab description. Most object families accept an "id" query
parameter to select a single element. GET /api/labs/session/tasks with
no name returns {"message":{"tasks":[{"id":"Configure the OSPF
underlay","weight":"1723486210001"}],"can_edit":true}; with
name=... it returns {"message":{"id":"Configure the OSPF
underlay","weight":"1723486210001","html":"<h2>...</h2>"}}.
validation returns separate YAML-backed validation activities, node
bindings, legacy task references, author capability, and the caller's
persisted check results and weighted completion. It never modifies
embedded text tasks or includes definitions in existing lab ZIPs.
ParameterInDescription
object reqpathOne of the x-objects values.
idqueryElement id, where the object family supports it.
namequeryTask title for GET /api/labs/session/tasks.
curl -sk -b jar.txt https://<host>/api/labs/session/nodes

Objects: configs console_guac_link html info interface interfaces line links multi_cfg_detail multi_cfg_list networkints networks nodes picturedata picturemapped pictures portcheck textobjects topology tasks validation wireshark workbook

POST /api/labs/session/{object}/{action}

Mutate the caller's open lab session (object/action fan-out).

The write fan-out of the lab page: object picks the family, action
the operation (flattened "object.action" pairs in x-actions). The
important families for an agent:
- nodes: add (body = the template form fields from
  /api/list/templates/{t} plus left/top), edit, delete, start, stop,
  shutdown, wipe, export (save running-config back into the lab),
  hibernate, freeze, isolate, lock/unlock, port/port_2nd (console
  port reassignment). start/stop/etc take {"id": node-id}.
  commit takes {"id", "mode"} and persists a STOPPED qemu node's disk
  overlay: mode=commit folds it into the shared base image every other
  lab is linked-cloned from (destructive, retroactive), mode=save_as
  additionally takes {"dest"} and writes a NEW image under
  addons/qemu/<dest> instead, leaving the base untouched. Admin only —
  both write appliance-global state. Fails if the node is running.
- networks: add/edit/delete a cloud/bridge; p2p (body src_id,
  src_if, dest_id, dest_if) wires two nodes point-to-point in one
  call.
- interfaces: edit connects/disconnects node interfaces (body id +
  interface map); setquality applies WAN impairment (delay, jitter,
  loss, rate) to a link; setSuspend / setSuspendtwo_way
  administratively suspend one or both directions; style/styles
  persist link styling.
- configs.edit saves a node startup-config (body id, data).
- lab.lock / lab.unlock toggle the lab's edit lock.
- textobjects / pictures / line: canvas annotations.
- workbook: guided-workbook page management.
- validation: additional task checks stored outside lab XML. save takes
  {base_revision,tasks}; import takes {base_revision,yaml,node_mapping}
  with optional explicit node mapping; export returns {filename,mime,yaml}.
  import with preview:true returns proposed node bindings without saving.
  save and non-preview import require EDIT_TASKS and an unlocked lab; export requires
  EDIT_TASKS. run takes {check_id}, executes one bounded check against
  the caller's lab node, and persists a server-derived result and score.
  Learners can run checks and inspect failed evidence but cannot submit
  pass/fail state or author definitions. Stale revisions fail with 409.
  Every check is explicitly user-triggered; opening the panel runs none.
- tasks: instructor-authored task management, backed by kind="task"
  workbook entries. Every task action requires EDIT_TASKS and an
  unlocked open lab. Bodies and successful responses are:
  add {"name":"Configure the OSPF underlay"} -> {"message":""};
  delete {"name":"Configure the OSPF underlay"} -> {"message":""};
  edit {"name":"Configure the OSPF underlay","new_name":"Configure
  OSPF Area 0"} -> {"message":""}; order
  {"src_name":"Task A","dest_name":"Task B"} -> {"message":""};
  update {"name":"Configure the OSPF underlay","content":"<h2>Objective</h2>"}
  -> {"message":{"id":"Configure the OSPF underlay","html":"<h2>Objective</h2>"}}.
  Task titles are 1-160 Unicode letters/digits/whitespace plus
  _-.,:;'"()&/; content is sanitized to a rich-text subset (headings,
  lists, tables, dividers, links, inline emphasis) and capped at
  256 KB after sanitization.
- wireshark: capture definitions - add, capture (start a capture),
  delete, focus, wifiview.
- multi_cfg: named config sets - add, active, edit, rename, delete,
  import, export.
- ai: the in-app agent assist - access, progress, plan, build.
- sdwan: versions/build of the SD-WAN controller-set factory.
- background.edit: canvas background flags (darkmode, 3D, grid).
All actions require an open session (factory/create first) and lab
edit permission for mutations; the lab lock refuses writes while
locked.
ParameterInDescription
object reqpathObject family (first token of the x-actions pairs).
action reqpathOperation (second token of the x-actions pairs).
curl -sk -b jar.txt -H 'Content-Type: application/json' \
  -d '{"id":1}' \
  https://<host>/api/labs/session/nodes/start

Actions: ai.access ai.build ai.plan ai.progress background.edit configs.edit interfaces.edit interfaces.setSuspend interfaces.setSuspendtwo_way interfaces.setquality interfaces.style interfaces.styles lab.lock lab.unlock line.add line.delete line.edit line.position multi_cfg.active multi_cfg.add multi_cfg.delete multi_cfg.edit multi_cfg.export multi_cfg.import multi_cfg.rename networks.add networks.delete networks.edit networks.p2p nodes.add nodes.delete nodes.edit nodes.export nodes.freeze nodes.commit nodes.hibernate nodes.isolate nodes.lock nodes.port nodes.port_2nd nodes.shutdown nodes.start nodes.stop nodes.unlock nodes.wipe pictures.add pictures.delete pictures.edit sdwan.build sdwan.versions textobjects.add textobjects.delete textobjects.edit tasks.add tasks.delete tasks.edit tasks.order tasks.update validation.save validation.import validation.export validation.run wireshark.add wireshark.capture wireshark.delete wireshark.focus wireshark.wifiview workbook.add workbook.delete workbook.edit workbook.order workbook.update

status

Host status, KSM/CPU toggles, network config, power, telemetry history (sub-app: /status/api.php).

GET /status/api.php

Host status reads (dispatch via ?action=).

Engine-cookie authenticated. Reads: system (ram/swap + admin cpu/
disk), nodes (running-node counts per type, admin), info (qemu
version, cores, KSM/cpulimit state, idle_timeout seconds), version
(engine release),
sessions (running lab sessions, admin), getSystemInfo /
getRunningNodes / getInfo / getClusterInfo (compatibility envelope
variants of the same), ksm / uksm / cpulimit (toggle state reads),
netcfg_get (management-interface config, admin), history_sys /
history_nodes (telemetry history, admin - see below).
history_sys: query range=1h|6h|24h|7d|30d - host CPU/RAM/swap/disk/
load series from the telemetry collector (10 s raw for 1h/6h, 5 min
rollups beyond); data.collector reports "down" when the daemon is not
sampling. history_nodes: same ranges plus optional lab=<session-id> -
top-10 per-node CPU/RAM series.
ParameterInDescription
action reqqueryOne of the x-actions values.
rangequeryhistory_sys / history_nodes: 1h, 6h, 24h, 7d or 30d.
labqueryhistory_nodes: restrict to one lab session id.
curl -sk -b jar.txt \
  'https://<host>/status/api.php?action=history_sys&range=1h'

POST /status/api.php

Host maintenance writes (dispatch via ?action=).

Admin-only writes: ksm / uksm / cpulimit (body {"state": bool}) and
their compatibility twins apiSetKsm / apiSetUksm / apiSetCpuLimit;
idle_timeout (body {"seconds": int}, 60-86400 - the site-wide idle/
session timeout every authenticated request slides forward; read back
via ?action=info's idle_timeout field); netcfg_set (management
interface reconfiguration); power (body {"op": "reboot"|"poweroff"});
disk_expand (grow the root filesystem into new free space).

Actions: apiSetCpuLimit apiSetKsm apiSetUksm cpulimit disk_expand getClusterInfo getInfo getRunningNodes getSystemInfo history_nodes history_sys idle_timeout info ksm netcfg_get netcfg_set nodes power sessions system uksm version
